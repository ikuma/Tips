# Hyperliquid 急変後の逆張り研究 — 2026-10-12

このパッケージは研究用です。発注機能はありません。数値の結果は `results/` のCSVと `summary_ja.txt` を参照してください。合成データによる単体テストは市場の実績に含めていません。

## 再現

Python 3.12 を使用。

```bash
python -m pip install -r requirements.txt
python -m unittest -v test_research.py
python baseline_only.py
python research.py --cohort both
python audit_trades.py
python audit_data.py
python summarize.py
```

同梱の固定済みデータを使うことで、APIの保存期限が過ぎても検証を再現できます。再取得する場合は `python fetch_data.py --stage all --workers 16`。取得キャッシュを再利用します。APIの将来の仕様変更や履歴保持期限によって再取得できない場合があります。Binance RESTへのHTTP 451を回避する処理はありません。別途公開されている公式ダウンロードデータを使っています。

## データと期間

- 原データ取得範囲：2026-03-18 04:00〜2026-10-12 04:00（Asia/Dubai、UTC+4、終端を除く）。
- 主解析：7日間の初期計算期間を置いた2026-03-25 04:00〜2026-10-12 04:00、201日。
- 時間分割：2026-07-03 16:00。前半は、その時刻までに観察72時間＋最大保有72時間がすべて終わるイベントだけを学習に使用。後半のイベント開始はこの時刻以降。
- コイン分割：GRASS・SOL・VVV・ZEC・ZROを学習から除外。前半の残り15銘柄で条件を選び、後半の同15銘柄と未学習5銘柄を別に検証する。
- 1時間足・fundingはHyperliquidの実データ。価格をBinanceで代用しない。
- OIはBinanceの公式daily metrics内の `sum_open_interest`（数量）を使用。ドル換算OIの価格依存を避ける。
- 成行比率はBinance USD-M futuresの5分足にある `taker_buy_volume` と総出来高から再構成。窓内の買い数量合計／売り数量合計であり、比率の単純平均ではない。REST比率との完全一致は検証できていない。
- `candleSnapshot` は直近5,000本だけ。5分足は約17日しかないため、5分足の価格停滞条件は短期補足に限定し、6か月の検証済み条件とは扱わない。両解析とも約定・ATR・損切り判定は1時間足ベース。
- 原始APIのタイムスタンプはUTC epochミリ秒のまま保存。結果CSVの表示時刻はDubai。

## 銘柄・出来高

候補群20銘柄は、取得時のHL出来高上位18銘柄に、依頼で指定されたUNI・AVAXを加えた現在のコホート。BTC, ETH, NEAR, HYPE, ZEC, SOL, STRK, PUMP, ENA, ONDO, ZRO, XRP, W, WLD, VVV, GRASS, TAO, SUI, UNI, AVAX。

現在の上場銘柄と出来高で候補群を作っているため、サバイバーシップと選択時点の偏りが残る。過去各時点の全銘柄上位20を再構築した研究ではない。取得時に日次2,000万ドルを満たす銘柄は16で、常に20銘柄が条件を満たすという意味ではない。

イベント時には、過去24本の `base volume × low` を合計した**取引高の保守的な下限**が2,000万ドル以上のイベントだけを採用。真のVWAPが不明なため、終値掛け出来高を正確なドル出来高と偽って使わない。境界近くの適格イベントを除外する可能性がある。

BRENTはこの20銘柄にも探索件数にも含めない。Binance対応OI・成行量がなく、原油先物の限月切替とoracleを別途扱う必要があるため、このデータでは同じ4指標の検証を行えない。

## イベント・条件判定

1. 確定済み1時間足の終値で、24時間±8%または168時間±15%を初めて検知する。同時に上方向と下方向の定義を満たすケースは方向が曖昧なため除外。標本開始時点ですでに続いていた急変を新規と誤認しないよう、開始時は未設定とし、24時間の平常状態を観測後に検知を有効にする。
2. 両方を同方向に満たす場合は24時間条件を優先し、急変前の価格をその期間の開始終値に固定する。
3. 同じ銘柄の再検知は144時間ロックする。加えて両方の急変条件から24時間連続で外れて初めて再設定可能。したがって、同一トレンドが続く間に何度もイベントとして数えない。重複抑制が厳しく、サンプル数を大きく減らす仕様である。
4. 検知時刻から72時間後まで、毎時73回評価。利用可能な条件が初めて同時成立した時だけ入る。各条件セット・各利確につき1イベント最大1件。
5. 価格以外の特徴量は5分の公開遅延を仮定し、その時点以前の値だけを使う。OIの前方引継ぎは最大10分まで。ローソク足や出来高の欠損を補間しない。
6. fundingはHLの1時間ごとの実績値×8を8時間相当として比較する。急騰時は正の過熱→低下、急落時は負の過熱→上昇を対称に定義。
7. 価格の極値は、急変開始価格の時点から判定時点までに実際に付けた最高値／最安値。高値・安値への同値到達も更新扱い。
8. BTC局面はイベント時点で既知の過去7日騰落率が+3%以上／−3%以下／その間。これは閾値の探索対象にせず固定。将来のBTC騰落で局面を分類しない。

## 出口・損益

- 判定足確定後の次の1時間足始値を基準に成行約定。ゼロ秒で正確に始値を取れるという保証はなく、スリッページを別途加算するモデル。
- SL：ショートは `max(既知最高値×1.002, 約定価格+1.5×ATR14)`。ロングは `min(既知最安値×0.998, 約定価格−1.5×ATR14)`。ATRは1時間足のWilder方式。
- TP：判定時点の極値をX、急変前の価格をP0として、`X + fraction × (P0−X)`。fractionは1/3・2/3・1。エントリー価格からの距離を3分割した定義ではない。目標がすでに約定価格より不利側なら、そのイベント・利確の取引を除外する。
- 同足でSL・TP両方に触れたらSLを先にする。SLを越えた始値ではその始値で損失を認識する。TPでの有利な窓開け改善は与えない。
- 最大保有72時間で未決済なら時間決済。これを置かないと右端で未決済取引を都合よく除外してしまう。
- 片道taker手数料4.5bp、片道スリッページ2bp。実際の口座の割引や履歴板データを反映した推定ではなく固定のコスト仮定。
- fundingの実際の支払時刻には数十msのずれがあるため、現金損益の時間バケットだけ時間単位に正規化。特徴量の利用可能時刻は元の時刻を維持。エントリー時の同時刻決済は受け取らず、次の時間から計上。
- fundingは `数量×oracle価格×実績rate` が正しいが、履歴oracleがないため前のHL1時間足終値を代理に使う。したがってfunding込み損益は完全な口座損益の再現ではない。
- 1Rは初期ストップまでの価格距離。手数料、スリッページ、窓開けにより実損失は−1Rを下回り得る。
- 最大DDは各取引の初期リスクを固定1Rとし、同時保有を足し合わせた1時間ごとの評価損益のピークから谷まで。決済損益だけのDDではないが、時間内の最大逆行と清算は再現しない。%への変換には資金配分・レバレッジ・同時リスク上限が必要。

## 探索と過学習対策

`config.json` に固定した有限グリッドを全探索する。連続値のすべてを試したという意味ではない。

| 系列 | 探索範囲 |
|---|---|
| funding | 過熱0.03/0.06/0.12%（8時間相当）、冷却0/0.01%、過熱を見る8/24時間、冷却平均1/3時間：24通り |
| 価格1h | 極値更新なし1/2/3/4/6/8本：6通り |
| OI | 1/3/6/12時間で1/3/5%以上減少：12通り |
| 成行比率 | 15/60/240分、方向を揃えた比率0.8/1/1.2以下：9通り |
| 価格5m補足 | 極値更新なし3/6/12/24本：追加4通り |

各系列を使わない選択肢を含め、主解析25×7×13×10=22,750ルール、3利確で68,250評価。短期補足25×11×13×10×3=107,250評価。Bonferroniの探索母数は両者合計175,500（基準の重複も含む保守的な補正）。

前半の開発15銘柄だけで選択し、後半の損益を見る前に候補を固定する。学習合格には30件以上・8週クラスター以上・「損益が正」と「基準より改善」の両方で補正後片側p<0.05を要求。後半は20件以上かつ期待値と基準との差の95%下限がともに正であることを確認する。後半と未学習銘柄を見て候補を選び直さない。

学習合格がなくても、学習10件以上の中で学習95%下限が高い最大3候補を**診断目的だけ**で後半に流す。これは推奨条件ではない。10件という基準は前半の標本数を確認後、グリッドの損益を見る前に診断用として設定した。30件の合格基準は変更していない。

95%区間は同じ7日ブロックの銘柄・イベントをまとめたクラスター標準誤差とt分布による。ブロックはepoch基準7日で、市場の同時変動を独立取引として数えない。ただし7日を超える系列依存、少数クラスター、裾の厚さで被覆率は保証されない。勝率は正の**コスト控除後R**の割合。平均利益は勝ち取引の平均R、期待値は勝ち負けを含む平均R。

基準比較は、同一イベントで直ちに逆張りした基準と、条件戦略の損益を比較する。条件不成立は0Rとし、取引を選りすぐっただけで「1イベントあたりの機会価値」が改善したと見せない。取引あたり平均R、条件成立時の対応基準平均Rも併記する。基準自体がTP無効のイベントは対応比較から除外する。

局面・銘柄・方向別の内訳は基準と固定候補について出力し、そこで新しい閾値を選ばない。全グリッドの後半結果を閲覧して最良値を選ぶ処理は実装しない。

固定候補と基準は、0/2/5/10bpの片道スリッページでも再計算する。コスト条件で最良の閾値を再選択しない。約定価格・ストップ幅が変わるため、同じシグナルでも決済結果が変わり得る。

## ファイル

- `results/hl_only_baseline.csv`：Binance欠損で対象を絞らないHLのみの無条件基準。
- `results/hourly_6m_baseline.csv`：4指標が揃うイベント上の比較用基準。
- `results/*_all_grid_train.csv`：全探索結果。短期補足は期間外検証とは呼ばない。
- `results/*_validation.csv`：基準・固定候補の時間分割、未学習銘柄、BTC局面、個別銘柄、方向別の結果。
- `results/*_trades.csv`：基準・固定候補のイベントID、価格、R、funding代理損益、決済理由。全グリッドの同じ取引を大量複製せず、コードから再生成できる。
- `results/fixed_signal_cost_sensitivity.csv`：固定シグナルのコスト感応度。`verification.json`には取引の再計算・重複・行数の検証結果を記録。
- `results/*_selection.json`：前半だけで選んだ候補と合格状態。
- `results/events.csv`, `data_coverage.csv`, `coin_folds.csv`：イベント・データ範囲・分割。
- `data/normalized/`：同梱する固定済み入力。計算と監査に必要な列を選び、生データの値・列名を保持したgzip CSV。Binanceの不要なトレーダー比率や価格列は含めない。
- `download_manifest_*.csv`：HTTP失敗・出典URL・取得キャッシュのハッシュ。失敗をゼロ件として捏造しない。
- `fetch_data.py`, `research.py`, `baseline_only.py`, `test_research.py`, `config.json`, `requirements.txt`：再現コードと仕様。

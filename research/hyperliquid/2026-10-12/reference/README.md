# Hyperliquid 参考指標と小幅利確の検証

## 今回の問い

1. 急変後の高値／安値更新が続きにくくなるか。
2. 指標を待つとエントリー後の最大逆行が小さくなるか。
3. 数分〜数時間の小反発を、損切り前にコスト込みで利確できるか。
4. 待機時間・価格位置・ボラ・BTC局面などが近いときにも、指標が追加情報を持つか。

前回は、急変の1/3・2/3・全戻しを利確にしていた。今回は利確幅を固定の小さい値に変更した。同じ履歴の別の結果指標を調べた探索的な追検証であり、新しい独立データでの検証とは呼ばない。

## 再現

Python 3.12。固定済み入力を同梱しているため、通常の再現ではAPIを呼ばない。

```bash
python -m pip install -r requirements.txt
python -m unittest -v test_reference.py
python reference_study.py
python make_report.py
```

`base_research.py` と `fetch_data.py` は、旧解析の時刻・データ読み込み・ATR・分割の関数を参照するために同梱。新解析の設定は `reference_config.json`。旧 `config.json` の最低30件の採用判定は**今回使用していない**。サンプル数にかかわらず計算できる結果を出し、不確実性を明示する。

## データ・イベント

- HL1時間足：約201日の主解析。評価範囲2026-03-25 04:00〜2026-10-12 04:00、ドバイ時間UTC+4。
- HL5分足：約17日。HL1分足：追加取得した約3日。長期の1分足・5分足検証ではない。
- OIと成行量は、前回取得したBinanceの公式公開アーカイブを固定して再利用。OIは数量、成行比率は窓内の買い／売り数量合計。
- 価格はすべてHL。Binance価格でHL約定を代用しない。
- 20銘柄候補の選び方は前回同様に現在の候補群。過去各時点の全銘柄上位20ではなく、サバイバーシップの偏りが残る。
- 急変は24h±8%または7d±15%。両条件が24h連続で平常に戻るまで再設定せず、同一銘柄144hのロックを維持。
- イベント時の24h出来高は `base volume × low` の合計による保守下限が$20M以上。
- 因果的に検知できた81イベント中、観察72h＋最大結果12hが全て揃う76イベントが主対象。旧解析73イベントは全て含まれる。必要な将来観測時間が144h→84hに短くなったことで3件を追加できた。
- 境界は2026-07-03 16:00 Dubai。観察＋結果が境界をまたぐ前半イベントは学習から除外。GRASS・SOL・VVV・ZEC・ZROは未学習銘柄。
- 指標は毎時評価。OI・funding・成行量は5分遅延を仮定。OIの古い値の持ち越しは10分まで。欠損価格を補間しない。
- 「ランドマーク」は同一イベント内の毎時観察点。5,824観察点を5,824件の独立トレードとは扱わない。主対象の観察点は5,539、独立イベントは76。

## 固定した指標・対照

| 指標 | 条件 |
|---|---|
| 価格停滞 | 1時間足でイベント内の既知極値を1本以上更新しない。同値到達は更新として扱う |
| OI減少 | 3時間前比で数量OIが3%以上減少 |
| 価格＋OI | 上2条件が同時成立 |
| funding冷却 | 24h以内に方向を揃えた8時間相当rateが0.03%以上、その後0.01%以下 |
| 成行の方向転換 | 直近1時間の比率が急騰時は買い／売り≤1、急落時は買い／売り≥1 |
| 価格＋OI＋成行 | 上記の組合せ |

対照は検知後即時、1h・3h・6hの単純待機、学習側での価格＋OIの成立までの中央値だけ待機。後者は**8h**であり、損益を見ず成立時刻だけで固定した。各ルール・各出口につき同一イベントで最初の1回だけ入る。

## 成功・出口

- 成功は、決めたネット利益目標へ損切り前に到達すること。将来の最高利益の時点を選んで決済しない。
- コスト控除後の利確目標：+1/10/25/50bp（0.01/0.1/0.25/0.5%）、または+0.25/0.5/1R。
- 片道taker fee 4.5bp、片道スリッページ2bp。合計は概ね13bp。小幅利確ではこの仮定に強く依存する。
- fundingは実績rateを使い、換算oracleの履歴がないため直前のHL1h終値を代理使用。ネット利確水準は既に受払したfundingにも合わせる。
- 損切りは前回指定を維持：既知極値±0.2%と、約定価格から1.5×1h ATR14の遠い方。このため小幅利確に対してストップ幅が非常に広いケースがある。
- 固定時間内にどちらにも触れなければ時間決済。1h足では1/3/6/12h、5m足では5/30/60/180/360/720分、1m足では1/30/60分。
- 利確と損切りが同じ足内にある場合は、損切り先行の下限と利確先行の上限を併記。始値ですでに利確または損切りを通過している場合は、その観測可能な順序を優先する。
- 最大有利変動MFEは診断用。損切り後に回復した価格も含むため、それを約定利益と偽らない。実行可能性は別の「TPがSLより先」の列を見る。
- 「利益率」は時間決済での微益も含む。「利確到達率」は設定したTPへ届いた割合。区別して保存。
- 平均Rは各取引の初期ストップ幅で規格化。平均ネット%は同額の想定元本で計算。両者の符号が異なる場合がある。

## 追加情報の検証

1. 同じイベントで、指標後の入口と即時入口を比較する。
2. 学習側だけで固定した8h待機との同イベント比較も行う。
3. 全毎時観察点で、イベント固定効果＋経過時間固定効果を使用。ATR比率・24h/7d急変幅・BTC7d騰落率・現在価格から極値までの距離・直近1hの方向を揃えた騰落を調整する。
4. 価格停滞が単に「既に極値から遠い」ことを示すだけでないか確認するため、極値距離をATRで割った区分と、価格速度の非線形項を追加した感応度分析を行う。

2つの回帰は因果効果を証明しない。二値アウトカムは線形確率モデルで、係数は確率差として読む。均等なイベント重みを使い、同じ週の観察をクラスターとして標準誤差を計算する。

今回の探索では6指標×4時間×6結果=144を補正母数に使用。事前に固定した主候補（価格＋OI、1h）の4結果も別に補正する。固定売買ルールの探索母数は11ルール×7利確×13の足・時間設定=1,001。前回の175,500評価まで含めた保守的な補正も保存。

週クラスターt区間は近似で、少数週・厚い損失尾部では被覆率を保証しない。全件利確した16件は損失尾部を観測していないため、平均Rのt区間・p値を空欄にして点推定だけを保存する。全件損失・一定の収益しかない場合も同様。到達率にはWilson区間も保存するが、こちらは独立試行を仮定した参考値で、銘柄間の連動を反映しない。

## 結果の入口

- `HL_reference_indicator_summary_2026-10-12.csv`：読みやすい主要比較。
- `report_ja.txt`：日本語の結果。
- `reference_results/first_entry_summary.csv`：固定ルール別の到達率、R、ネット%、初期ストップ幅、信頼区間、補正p値。
- `paired_event_comparisons.csv`：同イベントの即時入口との比較。
- `paired_frozen_clock_comparisons.csv`：同イベントの8h待機との比較。
- `adjusted_associations.csv` と `adjusted_associations_nonlinear.csv`：他の情報を調整した指標の寄与。
- `landmark_episode_weighted.csv`：イベントごとに平均し、観察数の多いイベントを過大評価しない内訳。
- `outcomes.csv`：全観察点の最大有利／不利変動と固定TPの結果。ランドマークの反復を独立取引数と数えない。
- `fixed_rule_trades.csv`：各ルール最初の1回の仮想売買。足・時間・利確・上下限を変えた別設定の重複は含む。
- `coverage.csv`, `outcome_coverage.csv`, `events.csv`, `landmarks.csv`, `audit.json`：検証範囲と欠損・独立件数の確認。
